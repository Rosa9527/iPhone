# iPhone（SillyTavern 悬浮球手机插件）

在 SillyTavern / TauriTavern 页面上加一枚可拖拽的悬浮球，点击后展开一台
高度仿真的 iPhone（iPhone 15 Pro 尺寸，393×852 设计稿）：灵动岛、状态栏、
主屏图标网格、Dock、Home 指示条与 iOS 式应用打开动画。

当前为 **v0.33.0**：悬浮球是 Apple LOGO，主屏网格有 QQ、微信、小红书、淘宝四个应用，
屏幕下方的 Dock 里是三个常用应用（世界书、设置、日志）。QQ 内页按
QQ NT 手机端（假设版本：安卓 QQ 9.0.x，界面还原以公开资料与旧版截图为参照）
做**纯界面仿真 + 基础页面跳转**，不含真实业务功能：

- **编辑资料（我的资料自定义）**：点消息页头部的「我的头像」（或 QQ空间
  大头像）进入 QQ 式「编辑资料」页——大头像卡 + 昵称 / QQ号 行式输入，
  即点即改、即时同步到消息页头部、聊天页我方消息头像与 QQ空间资料区。
  点大头像卡推开「选择头像」浮层：内置 21 款动漫 / 插画头像（默认款是纯 CSS
  灰底人形占位，其余 a1~a21 为同一批素材，选中带蓝勾；v0.31.0 起与微信、
  小红书共用同一份款式表）、上传本地图片（v0.19.0 起进入**拖动 /
  缩放取景**的裁剪编辑器，见下）或粘贴 https 图片链接。浮层右上角有独立的
  「保存」键：点了款式 / 链接 / 上传裁剪后先只更新选中态，按「保存」即时
  生效（表单类入口则先写进草稿，等本页「保存」一起提交）。资料存插件设置
  （宿主 `extensionSettings.IPhone.qqProfile`，
  本地预览回退 localStorage）；**昵称留空时默认使用酒馆的 `{{user}}`（当前人设名，
  v0.17.1 起全插件统一）**，QQ号留空回退占位演示数据——换人设 / 换聊天文件，
  「我」的昵称（消息页头部、QQ空间资料区、评论区署名、设置账户行）都自动跟着变。

- **上传头像取景（v0.19.0，QQ / 微信共用）**：选好本地图片后进入「调整头像」
  页——正方形裁剪框内拖动图片摆位（鼠标 / 触摸，屏幕像素按整机缩放换算，
  拖到边界自动停），底部滑杆（1~4 倍，以裁剪框中心为基准缩放）与滚轮缩放，
  框上有三分参考线；右上角「保存」把取景结果按原图坐标裁成 256px JPEG
  data URL（本机压缩，不上传），左上角返回则原样丢弃。整套编辑器是共享组件，
  QQ 与微信的 8 个头像入口（我的资料 / 个人信息 / 好友 / 群聊 / 添加好友 /
  创建群聊 / 添加朋友 / 发起群聊）都会用到，皮肤随所在应用（QQ 蓝滑块、
  微信绿滑块 + 灰底）。

- **添加好友 / 创建群聊**：点消息页右上角「+」弹出白色小菜单（创建群聊 /
  加好友，对照真实 QQ 的加号面板，点空白处收起）；联系人页头部的加好友
  按钮直达添加好友表单。两个表单为 QQ 式页面：导航栏右上角蓝色「添加 /
  创建」动作 + 大头像卡（点开「选择头像」浮层，与编辑资料同一套内置头像 /
  上传 / 图片链接）+ 昵称（群名称）/ QQ号（群号）行式输入；创建群聊多一张
  成员卡，勾选加入群聊的好友（至少 2 人，无好友时提示先添加）。校验不过
  在表单内红字提示；提交后好友 / 群聊立即出现在消息页会话列表与联系人页
  对应分组。数据存插件设置（宿主 `extensionSettings.IPhone.qqData`，
  本地预览回退 localStorage），会话列表的未读红点暂不做。

- **好友资料（聊天页右上角菜单）**：好友聊天页点右上角「≡」进入 QQ 式
  「好友资料」页——大头像卡（点开与编辑资料同一套「选择头像」浮层：内置
  款式 / 上传 / 图片链接）+ 昵称 / QQ号 行式输入（预填当前资料）+
  「她的QQ空间」入口行（空心星 + 右箭头，进入她的空间：同一套横幅与动态流，
  资料区显示她的头像与昵称）。**她的空间只看她的动态**（v0.20.0）：动态流按
  联系人的 id 过滤，只有 TA 发出的帖子，别人的帖子不会混进来；空间里下拉刷新
  也只让 TA 发一条新动态（提示词名单收窄成 TA 一人，AI 写错发布者就整条作废
  并提示「刷新失败」，不会污染数据）。右上角「保存」写回 qqData，会话列表 /
  联系人 / 聊天页标题即时同步；群聊的「≡」暂不响应。

- **消息页**：头部（头像 / 昵称 / 在线状态 / 添加）、白色圆角面板（搜索 +
  会话列表）、底部「消息 / 联系人 / 动态」三标签。会话列表由已添加的
  好友 / 群聊数据渲染（好友在前、群聊在后），暂无数据时显示引导空态。
- **聊天页**：点会话进入。头部：返回 + 标题（群聊为「群名(成员数)」，无
  头像无耳朵）+ 状态行（好友：绿点在线；群聊：成员数）+ 右侧菜单（好友点开
  「好友资料」页，内含「清空聊天消息」与「删除联系人」两条红色警示行 +
  确认卡——前者清空后楼层从空记录续写，后者把好友从数据删除（所在群聊
  成员自动收缩、会话与联系人列表即时刷新），并关闭聊天页与资料页；楼层的
  既有记录按设计保留）。好友会话为真输入框 + 气泡消息流（我方右蓝、对方左白带头
  像）：聊天记录存插件设置（`friend.messages`，最多 200 条），发送调用
  「设置 · API 连接」配置的模型——OpenAI 兼容 `/chat/completions`，跨域经酒馆
  后台代理（`/api/backends/chat-completions/generate`）失败自动直连回退。
  **提示词（v0.10.0 重做）**：system 一条消息按顺序装——① 角色扮演系统提示词；
  ② 选定的世界书内容（引擎激活 − 玩家在世界书应用里排除的条目）；③ 酒馆
  history 最新五条（SillyTavern 聊天楼层，旧→新；跳过隐藏楼层与本插件的
  `<iPhone_Message>` 记录楼层）；④ 输出格式约定——每行 `联系人：「消息内容」`，
  一行一条。之后按顺序拼本会话已有消息。回复按约定格式逐行解析为多条 QQ
  消息（一条一行 = 连续多条短消息气泡），没有格式行时整段兜底为一条；上限
  10 条。子请求不经过酒馆生成管线，发送前会把 `{{user}}` / `{{char}}` 就地解析
  成人设名 / 角色名。等待时显示「对方正在输入…」气泡，失败在流内显示红色
  错误行。**长按 / 右键单个气泡**弹出深色「删除」菜单，可删除单条消息
  （本地与存储一起删，已同步的楼层游标相应回退）。**群聊会话（v0.12.0）**：
  AI 同时扮演除玩家外的所有群成员——请求比私聊多一段 `<group_members>`
  群成员列表（按建群成员自动生成），输出格式为每行 `成员名：「消息内容」`，
  回复解析成带成员头像与发言人名字标签的群聊气泡（我方仍右蓝；名单外名字
  用名字首字字牌兜底，解析不到名字沿用上一条发言成员 / 落到成员第一位）；
  聊天记录存 `group.messages`（含发言人 name 字段，最多 200 条），楼层同步
  写 `群「群名」的QQ群聊记录：` 段；等待时显示「有人正在输入…」。
- **世界书**：Dock 独立应用（v0.29.0 起移入屏幕下方的常用应用区，设计参照同目录
  SoulLink 扩展的世界书功能）。
  条目激活完全交给宿主酒馆引擎（`ctx.getWorldInfoPrompt` 干跑，插件不做关键词
  扫描）：生效世界书 = 激活结果里的书 + 角色世界书（/getcharbook 兜底）+
  聊天绑定 + 人设书 + 全局多选框，逐本 `ctx.loadWorldInfo` 展开全部条目。
  页面按书分组可折叠手风琴：书名 + 条目计数、每书独立搜索框、条目行 =
  勾选框（**勾选 = 排除**）+ 显示名 + 徽章（常驻 / 禁用 / 注入位置 / 本次触发 /
  已排除）。被排除的条目拼 QQ 聊天提示词时跳过，不发给 AI；未激活的普通条目
  本次不发送（与酒馆行为一致），常驻条目始终发送。排除状态存插件设置
  （`worldInfo.excluded`，书名 → uid 数组，身份键为「书名 + uid」），支持一键
  清除全部排除。降级：宿主没有世界书引擎时空态提示；引擎只回整段文本时
  显示黄色横幅（无法按条目排除，文本仍会注入）。
- **iPhone_Message 楼层（聊天记录同步进酒馆聊天）**：好友聊天每次产生新记录
  （发出消息 / 收到回复）后，插件先扫描酒馆当前聊天的**最新楼层**——若楼层全文
  （去首尾空白）以 `<iPhone_Message>` 开头、以 `</iPhone_Message>` 结尾且中间内容
  全属标签内部，就认定是记录楼层并**原地把新对话追加进标签内部**（不新建楼层、
  不破坏最外层标签）；否则**新建一个楼层**，楼层全文用
  `<iPhone_Message>...</iPhone_Message>` 包裹，作为当前聊天的专用记录楼层。
  标签内按段记录（v0.21.0 起**每段各自再套一层标签**，段头留在标签内首行；
  v0.23.0 起段标签改用**方括号**——只有最外层 `iPhone_Message` 保留尖括号）：
  `[QQ_私聊_联系人]` 包 `与「联系人」的QQ聊天记录：`、`[QQ_群聊_群名]` 包
  `群「群名」的QQ群聊记录：`、`[QQ空间动态]` 包 `QQ空间动态：`，微信侧同理
  （`[微信_私聊_…]` / `[微信_群聊_…]` / `[朋友圈动态]`）。段与段之间**不空行**
  （v0.24.1 起）——闭合标签的下一行直接就是下一段的开标签，形如
  ```
  <iPhone_Message>
  [微信_私聊_杨知世]
  与「杨知世」的微信聊天记录：
  {{user}}：「在吗亲爱的？」
  杨知世：「在。」
  [/微信_私聊_杨知世]
  [微信_私聊_木之本樱]
  与「木之本樱」的微信聊天记录：
  木之本樱：「诶？怎么啦～」
  [/微信_私聊_木之本樱]
  </iPhone_Message>
  ```
  标签名里的空格与标签非法字符统一换成下划线。段头 + `{{user}}：「内容」` /
  `联系人：「内容」` 逐条对话行（内容统一包「」）——用户侧直接写酒馆宏
  `{{user}}`（宿主构建提示词时才解析成人设名，楼层 UI 里显示宏本体），同楼层
  多人记录按段分开（同一会话永远只有一段、一个标签）；空间动态段每条动态一个
  `◆ 名字：正文` 块（缩进的点赞 / 评论行，含玩家回复），该段在动态或评论变化时
  整段重写（v0.17.0 起，见下）。旧格式的楼层照常读取、在下一次同步时自动原地
  迁移：裸段头（无标签）按段头反推标签补上，v0.21.0–v0.22.x 的尖括号段标签
  （`<QQ_私聊_…>`）换成方括号，段间残留的空行一并收掉，重复的旧段顺带合并
  清理。同步进度
  （已写入条数）记在 `friend.floorSynced`，每次只追加新消息，不重不漏；最新楼层
  被其他内容取代时会按规则再建新楼层。
  楼层按 **{{char}} 的普通楼层**创建（`is_user` / `is_system` 均为 false，名字用
  当前角色名），正常显示并计入 AI 上下文。注意：TauriTavern 的 `is_system` 就是
  「隐藏楼层」标记（眼图标隐藏功能改的就是它），系统消息既会被界面隐藏、也会被
  排除出提示词——v0.9.6 曾误用导致楼层被隐藏，v0.9.7 改正。落盘走宿主
  `saveChat`；宿主上下文不可用（本地裸预览）时静默跳过。
- **联系人页**：按真实界面复刻——头部（头像 / 居中「联系人」标题带蓝色
  下划线 / 加好友按钮，随 Tab 切换）、搜索条、新朋友 / 群通知大字行；
  子页签仅 **分组 / 好友 / 群聊**（可切换）：分组视图含 ▶特别关心 0/0
  （收起）与 ▼我的好友（在线/总数计数，点表头折叠展开），好友行为头像 +
  名字 + 绿点在线状态（QQ号不外显），群聊页签列出已创建的群（人数，
  可点开聊天）。三个面板均由 qqData 数据渲染，空数据时显示「去消息页
  右上角 +」引导。
- **动态页**：按真实界面复刻完整入口列表——头部（头像 / 「动态」标题 /
  宫格按钮，随 Tab 切换）、搜索条与三组入口行（空间动态 / 脑洞秀；
  游戏中心 / 小游戏 / QQ经典农场；漫剧 / 小说与动漫），右侧带灰色副标题
  （金铲铲新赛季 / 比熊狗狗上线 / 我有个历史微信群）、入口缩略图与红点角标。
  **仅「空间动态」可点**进入 QQ 空间，其余入口纯展示不响应。
- **QQ空间 · 空间动态**：点「空间动态」直接进入个人空间单页，向下滚动看
  好友动态。页顶：樱花横幅 + 悬浮导航（半透明返回钮 /「空友爱看」胶囊 /
  铃铛 / 设置）、大头像压横幅、昵称 + LV / 续费徽章、「总量 3568」、
  说说 / 日志 / 相册 / 留言 / 更多五宫格、「分享新鲜事…」输入条（配图 /
  AI 图标）。动态流：小头像 + 蓝色昵称、文字 / 灰底长文块（截断 +
  「查看全文」）、图片格、时间与点赞 / 评论 / 分享操作行、蓝色点赞名单、
  评论区（「A 回复 B」链、加粗斜体、更多）与每条动态尾部「说点什么吧…」
  胶囊。滚过横幅后顶部导航自动切换为白色「空间动态」标题栏。
  **下拉刷新（v0.20.0 起带旋转小圈）**：在空间顶部下拉超过 64px 松手，指示条
  里出现蓝色小圈（拖动阶段就在转，刷新文案「正在生成新的动态…」/ 访客空间为
  「正在生成 TA 的新动态…」），调一次对话 API 生成 1~3 条新动态；指示条内容
  贴底对齐、刷新态高 72px，小圈与文案完整落在手机状态栏图标下方（不会和灵动岛 /
  电量叠在一起）。**回复帖子**（v0.17.0）：点任意动态下的胶囊弹出输入行，写下评论回车 /
  点「发送」——玩家评论（评论区署名默认就是酒馆 `{{user}}` 人设名，v0.17.1
  起与「我」的昵称同源）立刻落到该动态评论区（带「我」标）并同步进
  iPhone_Message 楼层，随后调一次对话 API 由 AI 生成 1~3 条新评论回复
  （贴主 / 其他联系人应声，「A 回复 B」指向玩家、贴主或评论区里的人），
  同样落盘并刷新楼层；同一条动态可反复回复，回复指导与格式在「设置 ·
  动态提示词」里可改，请求失败时评论不丢、卡片内红字提示原因。提示词里
  `{{user}}` 照常解析成酒馆人设名（与私聊 / 群聊一致）；只有编辑资料填过
  自定义QQ昵称时两个名字才会不同，此时另附玩家身份说明把两者对应起来
  （模型把 QQ 昵称当成第三人、或替玩家发言都会被组装方纠正）。

- **设置（iOS 系统设置高保真仿真）**：Dock「设置」应用按系统设置风格还原——
  34px 大标题滚动折叠入毛玻璃导航、白色内嵌分组列表（44px 行高、29px 彩色
  扁平行图标、文字左缘内缩分隔线）。主页自上而下为：搜索框（布局缓冲）、
  Apple 账户行（昵称跟随酒馆 `{{user}}`，与 QQ 里「我」的昵称同源）与其下方
  的「API 连接」入口。

  - **API 连接**：服务器地址 + API 密钥（密钥可点眼睛显隐），表单为
    iOS 的「标签居左、输入居右」行式布局；「连接」是导航栏右上角的蓝色文字
    动作，拉取 OpenAI 兼容 `/models` 列表，状态以分组脚注小字实时显示（成功
    绿 / 失败红）。跨域地址优先经 TauriTavern 宿主代理
    （`/api/backends/chat-completions/status`）转发，失败自动回退直连。
  - **模型选择**：「模型」行推入 iOS 式勾选列表子页（选中项右侧蓝勾），也可在
    「自定义模型」行直接输入；主屏行尾灰字同步显示当前模型。
  - **请求控制**（功能同 Kaleidoscope 的 API 设置）：「并发限制」推入勾选子页，
    可选「不限制」或预设档位（1/2/3/5/8/10），也可在「自定义上限」行输入
    1–99 的数值（默认 3，请求按名额排队，见 `js/host.js`）；「思考强度」推入
    勾选子页，对应 OpenAI 兼容参数 `reasoning_effort`

    扩展（包括本插件作者没见过的）都自动覆盖。注册表条目有两种生命周期，对应
    两条取材路径：
    - **实时读**：手机要发请求时直接读注册表。常驻型扩展（生物追踪、世界引擎
      等，注入长期留在注册表里）这样就能拿到此刻的值。
    - **快照**：发送期扩展（万华镜等）只在「点发送 → 生成结束」之间把内容写进
      注册表，之后清空——只在手机里聊天、从不往酒馆发消息的玩法下注册表永远
      是空的，只靠实时读什么都看不到。所以酒馆拼主请求时（提示词就绪事件
      `CHAT_COMPLETION_PROMPT_READY` / `GENERATE_AFTER_COMBINE_PROMPTS`）额外
      抓一份快照，那是主线模型真正看到的原样字节，含宿主做过的宏替换。
    合并规则：**实时读到的打底，快照里的按键补齐**（同一键以实时值为准）——
    这样发送期注入在被清空后仍能从上一轮快照里带到，代价是扩展关掉注入后旧值会
    留到下一次酒馆组装为止（注册表里「清空」与「不再注入」都是空值，通用机制下
    无法区分，可接受）。页面里每条据此标注**实时**或**上一轮**。

    介绍语不只贴标签，还交代了用法与禁忌：告诉模型这是其他扩展提供的

    与剧情进展要与之相符，**但不要把里面的数值直接念进对话、也不要提起这份资料
    本身**——这段内容多是 `好感度: 42` 这类状态数据，不约束就容易被模型当台词读出来。

微信联系人与朋友圈 / 钱包余额（含零钱评估结果与理由，v0.27.0） / 小红书网友与笔记 /
淘宝商品、购物车与订单（v0.28.0，订单会随零钱扣款一起变）
都随当前聊天文件走（v0.15.0 起，`chatMetadata.iPhone`）；世界书等其余应用仍为
占位演示数据。

- **日志（深色控制台，架构参考 SoulLink 的日志系统）**：Dock「日志」应用是
  一块后台常驻日志缓冲的查看器——关闭应用捕获不中断，重开即重渲染。捕获
  范围：console 输出（log/info/warn/error/debug）、window 错误与 Promise 拒绝、
  全局 fetch 旁路（请求/响应头与体，状态码定级：≥500 错误 / ≥400 警告）、
  宿主事件桥接（chatChanged / messageSent / generationEnded 等，宿主上下文
  不可用时静默跳过），以及插件自身的 iphoneLog（来源「插件」）。列表支持
  级别 / 来源筛选（带实时计数）、搜索（含详情，防抖）、暂停 / 继续（暂停期间
  新日志计数 +N，继续后一次性显示）、连续重复折叠（×N 徽标）、点行展开完整
  详情（请求体 / 响应体原文）、贴底自动跟随 + 「回到最新」浮钮、复制全文与
  导出 JSON；对话接口的完整请求/响应体（最多保留 10 份）经「请求体」按钮
  单独导出最近 3 份（不脱敏截断，供排查提示词）。敏感信息自动
  脱敏（api_key / Authorization / Bearer / sk-… / tauri-invoke-key → ***）。
  已知噪音（世界书扫描、宏变量 dump、内部保存、非模型 IPC 等）可用「噪音
  过滤」开关一键屏蔽；内存容量（500–20000 条）在底栏选择并随设置持久化。
  对外暴露 `iPhoneLogs` 全局 API（debug/info/warn/error/log/clear/getEntries/
  setMaxEntries），供其他脚本与控制台手动写日志。

## 设计要点

- **缩放策略**：内部全部按 393×852 设计稿像素书写，JS 按窗口大小对整机
  `transform: scale()`，任意窗口下细节比例一致（缩放上限 1.35，矢量内容缩放仍清晰）。
- **应用打开动画**：应用层以图标中心为 `transform-origin` 从 0.12 放大到全屏，
  主屏同时压暗缩小（`is-under-app`），模拟 iOS 层级纵深；关闭反向播放。
  Dock 图标走同一条管线，动画原点按 Dock 里的位置换算。
- **主屏与 Dock 的分工**：应用注册表（`IPHONE_APPS`）里 `dock: true` 的进屏幕
  下方的毛玻璃停靠栏（真机 Dock 观感——只有图标没有名称），其余进主屏网格；
  两处都用同一个 `buildIphoneAppIcon` 渲染，新增应用只需在表里加一条。
- **层级**：遮罩 21000 / 悬浮球 21100，压在宿主与其他扩展浮层之上。
- **设置持久化**：纯 UI 部分不读宿主；「设置 · API 连接」引入的配置经
  `js/host.js` 的 `iphoneGetContextSafe()` 按 Kaleidoscope 模式接宿主
  （`extensionSettings.IPhone`），宿主不可用时回退 localStorage，两种路径
  都不影响悬浮球 / 主屏装配。
